# BIOS 309 → 310

**Device:** ASUS ROG Zephyrus G14 GA403WR (2025)

**ASUS posting dates:** 309: September 30, 2025; 310: July 22, 2026

**Research date:** October 26, 2026

ASUS lists “Optimize system performance” for these packages. The image comparison finds an AMD platform update, new CPU-core setup controls, ACPI changes and changes to USB4 and firmware memory handling.

## Plain-language takeaway

- **CPU settings:** ASUS adds firmware controls for how many performance and efficient cores to enable. Both default to “All.” The BIOS also gains code to report the available and selected counts to software. The labels come from ASUS's AMD firmware; menu visibility and changing the counts need a hardware check.
- **Graphics and freezes:** ASUS changes when one NVIDIA power-control table updates its GPU-state flag. That could affect power transitions on systems that use that table. Another packaged NVIDIA table stays identical, and the separate GPU wait loop still has no timeout. This comparison does not establish that 310 fixes the reported random freezes.
- **USB-C/USB4:** AMD changes how the BIOS polls for a USB4 router during startup. The new path uses a different timer context and removes a delay inside the loop. Any effect on docks or wake reliability needs testing.
- **AMD firmware:** ASUS includes newer CPU microcode, AGESA, power-management and security-processor components. Their version changes are confirmed; performance and battery-life gains remain unmeasured.
- **Memory handling:** The BIOS adds zeroing of an AMD SMM memory region and changes an IPv6 setup screen to use an allocated, expandable buffer. These are code changes with a security or robustness purpose inferred from their behavior. No specific CVE is assigned here.
- **Charging and fans:** The recovered EC code shows a version/date update and address movement. No new charging threshold, fan curve or power-budget policy was identified in this pair. The charging changes in [310 → 312](310-to-312.md) belong to that later update.

Hardware validation is pending. This report compares distributed firmware files and does not include a BIOS downgrade, flash operation or before/after crash-rate test.

## GPU transitions and the freeze claim

In the `OemNv2T` SSDT, ASUS moves the EC `VGAT` write ahead of the main GPU power-state check. The `_ON` method writes 1; `_OFF` writes 0. The old locations sat inside an `ECOK`-guarded branch while the method held another EC mutex. The new ordering removes those nested acquisitions for these writes.

That is a concrete power-sequencing change. Its applicability depends on which NVIDIA table the firmware installs. The packaged `Opt2Tabl` alternative is byte-identical across 309 and 310 and already uses earlier state updates.

The DSDT's separate GPU-enable path still sleeps for two seconds and then polls `NVPS` every 100 ms while it equals 1. Neither version supplies an explicit timeout for that loop. A stuck flag could stall that AML call; the code alone does not identify the cause of a whole-system freeze.

See the [ACPI review](../research/309-310-acpi.md) for the seven changed table templates, the unchanged alternative and the limits of a packaged-table comparison.

## SEC-01: Secure Boot defaults

The authenticated `dbx` bodies have different raw hashes, but their parsed revocation contents match: **371 SHA-256 records and one X.509 certificate**, with **0 added and 0 removed**. Both bodies occupy 18,761 bytes. Authentication data can change without adding a blocked executable. See [dbx-diff.json](../data/309-310/dbx-diff.json).

`TlsDxe` is also byte-identical in this pair. The OpenSSL patch matches and 59 additional default `dbx` hashes documented for [310 → 312](310-to-312.md) do not belong to 309 → 310.

## Other changes and limits

ASUS rebuilds or changes setup, flashing, PCI-resource, TPM/PSP and AMD initialization modules. The inventory includes **140 changed/new PE instances** and **176 changed TE instances**. Those counts include repeated copies, changed identifiers and layout differences; they do not count fixes.
