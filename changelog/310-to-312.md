# BIOS 310 → 312

**Device:** ASUS ROG Zephyrus G14 GA403WR (2025)

**ASUS posting date:** October 21, 2026

**Research date:** October 25, 2026

ASUS's release note says “Optimize system performance.” Comparing the published EZ Flash images shows changes to battery charging, power settings after unplugging, Secure Boot revocations and certificate-handling code.

## Plain-language takeaway

- **Charging near 80%:** ASUS changes how battery-care mode stops and resumes charging. In the examined path, the new code remembers reaching 80% and clears that state at 78% or below. That suggests a pause-and-resume band around the limit.
- **Running on battery:** ASUS changes the starting power settings after you unplug the charger. The examined paths select higher processor power budgets in some modes, subject to other limits. Any effect on speed or battery life needs measurement.
- **Security:** ASUS adds 59 fingerprints used to identify blocked startup software, plus code matching two certificate-handling fixes. Whether an attacker could trigger those certificate bugs through this BIOS remains unknown.
- **Wi-Fi:** One country setting appears to change permission to use 6 GHz Wi-Fi in Vietnam. The corresponding US setting stays the same.
- **BIOS menus:** ASUS changes menu-control and layout code. The visible effect remains unresolved.

Hardware testing is pending, including custom charge limits and the Windows Wi-Fi driver. Battery life, fan noise and gaming performance need before/after measurements.

## EC version and charging

ASUS includes a new ITE51300 EC application build:

| Field | 310 | 312 |
|---|---|---|
| Version | `03.10F#` | `03.12F#` |
| Build | `2025/10/02 b02#` | `2026/09/17 b01#` |
| Board | `ASUS NJT(GA403W_MB1)` | Same |

In battery-care mode, the new code sets a state bit at relative charge ≥80%. It clears the bit at or below the lower threshold, initialized to 78 in the examined path. Several charging routines use that state, including a path that writes zero requested current to the charger.

The old code depended on direct comparisons to 80 in some decisions. The new state bit supports stop/resume behavior around the limit, including charge values that pass the exact threshold. The effect on G-Helper's custom 60% limit remains unknown.

## Power policy after unplugging

One EC routine clears the AC-present flag and calls a policy reset. In the reset, ASUS changed six selector bytes from 8 to 3, with two mirrored state bytes following the new value. Downstream code selects different rows from unchanged power-budget tables.

For one table, selector 8 chooses `[15, 18, 36, 80]`; selector 3 chooses `[25, 31, 62, 80]`. Another table changes the selected row from `[23, 27, 56, 100]` to `[38, 47, 82, 100]`. The EC passes resulting budget values through a ×1000 conversion to a processor-command path.

This supports a less restrictive initial battery policy in those paths. Other code clamps the values and changes the selectors, so these rows do not establish a lasting CPU wattage, an FPS gain or a change to a fan curve. The [EC notes](../research/310-312-ec.md) trace the call chain and retain the table coordinates.

## SEC-01: Secure Boot revocations

The default `dbx` payload grows from **371 to 430 SHA-256 entries**. ASUS adds **59**, removes **0**, and retains the same X.509 certificate, `ASUSTeK Notebook dbx Certificate`.

The authenticated payload grows from 18,761 to 21,593 bytes. The difference is 2,832 bytes, or 59 records of 48 bytes: a 16-byte owner and a 32-byte signature. See the [added entries](../data/310-312/dbx-diff.json).

This comparison covers the payload in the BIOS package. A laptop's enrolled `dbx` may already contain some entries from Windows or another update. The executable identities behind the added hashes remain unresolved.

## WLAN-01: MediaTek country policy

The decompressed DSDT has one functional byte change:

```text
Path:   \_SB.PCI0.GPP5.WLAN.MTCL.MLSB
Offset: 0xE847 in the DSDT
Before: 0xD8
After:  0xDC
```

The other changed DSDT byte is the checksum, `0xB9 → 0xB5`. The table remains 66,275 bytes long.

MediaTek's [driver implementation](https://github.com/torvalds/linux/blob/master/drivers/net/wireless/mediatek/mt76/mt792x_acpi_sar.c) and [structure definitions](https://github.com/torvalds/linux/blob/master/drivers/net/wireless/mediatek/mt76/mt792x_acpi_sar.h) map the changed bit to Vietnam's 6 GHz policy. The table has mode 1. The US bit stays the same. Windows-driver handling remains untested.

## Libraries and setup

The disassembly matches fixes for OpenSSL's delta-CRL null dereference and DANE certificate ownership problems. The [UEFI notes](../research/310-312-uefi.md) include upstream commits and module RVAs. These matches do not prove a full OpenSSL version upgrade or a reachable attack on this laptop.

ASUS also changed the setup interface's child-control property handling. Most of the large AMITSE binary difference comes from moved routines and data. A whole-file diff overstates its functional scope. New visible options and password-policy changes remain unconfirmed.
