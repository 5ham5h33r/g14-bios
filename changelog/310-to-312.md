# BIOS 310 → 312

**Device:** ASUS ROG Zephyrus G14 GA403WR (2025)

**ASUS posting date:** October 21, 2026

**Research date:** October 25, 2026

ASUS's public note says “Optimize system performance.” I compared the published EZ Flash images to recover a more useful list. The strongest findings concern battery charging, the power policy after unplugging, Secure Boot revocations and two OpenSSL fixes.

## Plain-language takeaway

- **Charging near 80%:** ASUS changes how the laptop stops and resumes charging when battery-care mode is on. The new code remembers reaching 80% and, in the mode examined, allows charging to resume at 78%. This may make charging around the limit more consistent. I have not tested the behavior on a laptop or with a custom 60% limit.
- **Performance after unplugging:** ASUS changes the starting power settings when you disconnect the charger. Some settings allow higher processor power budgets. Other limits still apply, so I cannot promise faster games or say how long the change lasts.
- **Security maintenance:** ASUS adds 59 fingerprints to the built-in Secure Boot blocklist, which helps the laptop reject matching software during startup. It also includes code matching two fixes in a library that checks digital certificates. I have not shown that an attacker could trigger those bugs on this laptop.
- **Wi-Fi:** One change appears to concern permission to use 6 GHz Wi-Fi in Vietnam. The corresponding US setting stays the same. I have not tested how the Windows driver handles it.
- **BIOS menus:** ASUS changes code that handles menu controls and layout. I have not confirmed a visible difference or a new setting.

The clearest practical changes concern charging and power settings after unplugging. I have no hardware measurements showing better battery life, quieter fans or higher frame rates.

## EC version and charging

ASUS includes a new ITE51300 EC application build:

| Field | 310 | 312 |
|---|---|---|
| Version | `03.10F#` | `03.12F#` |
| Build | `2025/10/02 b02#` | `2026/09/17 b01#` |
| Board | `ASUS NJT(GA403W_MB1)` | Same |

In battery-care mode, the new code sets a state bit at relative charge ≥80%. It clears the bit at or below the lower threshold, initialized to 78 in the examined path. Several charging routines use that state, including a path that writes zero requested current to the charger.

The old code depended on direct comparisons to 80 in some of those decisions. I infer that ASUS changed stop/resume behavior around the limit, including cases where charge passes the exact threshold. I have not measured the result or tested G-Helper's custom 60% limit.

## Power policy after unplugging

One EC routine clears the AC-present flag and calls a policy reset. In the reset, ASUS changed six selector bytes from 8 to 3, with two mirrored state bytes following the new value. Downstream code selects different rows from unchanged power-budget tables.

For one table, selector 8 chooses `[15, 18, 36, 80]`; selector 3 chooses `[25, 31, 62, 80]`. Another table changes the selected row from `[23, 27, 56, 100]` to `[38, 47, 82, 100]`. The EC passes resulting budget values through a ×1000 conversion to a processor-command path.

This supports a less restrictive initial battery policy in those paths. Other code clamps the values and changes the selectors, so these rows do not establish a lasting CPU wattage, an FPS gain or a change to a fan curve. The [EC notes](../research/310-312-ec.md) trace the call chain and retain the table coordinates.

## SEC-01: Secure Boot revocations

The default `dbx` payload grows from **371 to 430 SHA-256 entries**. ASUS adds **59**, removes **0**, and retains the same X.509 certificate, `ASUSTeK Notebook dbx Certificate`.

The authenticated payload grows from 18,761 to 21,593 bytes. The difference is 2,832 bytes, or 59 records of 48 bytes: a 16-byte owner and a 32-byte signature. See the [added entries](../data/310-312/dbx-diff.json).

This comparison covers the payload in the BIOS package. A laptop's enrolled `dbx` may already contain some entries from Windows or another update. I have not mapped each new hash to an executable.

## WLAN-01: MediaTek country policy

The decompressed DSDT has one functional byte change:

```text
Path:   \_SB.PCI0.GPP5.WLAN.MTCL.MLSB
Offset: 0xE847 in the DSDT
Before: 0xD8
After:  0xDC
```

The other changed DSDT byte is the checksum, `0xB9 → 0xB5`. The table remains 66,275 bytes long.

MediaTek's [driver implementation](https://github.com/torvalds/linux/blob/master/drivers/net/wireless/mediatek/mt76/mt792x_acpi_sar.c) and [structure definitions](https://github.com/torvalds/linux/blob/master/drivers/net/wireless/mediatek/mt76/mt792x_acpi_sar.h) map the changed bit to Vietnam's 6 GHz policy. The table has mode 1. The US bit stays the same. I have not tested the proprietary Windows driver's handling of this table.

## Libraries and setup

The disassembly matches fixes for OpenSSL's delta-CRL null dereference and DANE certificate ownership problems. I cite the upstream commits and give the module RVAs in [the UEFI notes](../research/310-312-uefi.md). These matches do not prove a full OpenSSL version upgrade or a reachable attack on this laptop.

ASUS also changed the setup interface's child-control property handling. Most of the large AMITSE binary difference comes from moved routines and data. A whole-file diff overstates its functional scope. I have not established a new visible BIOS option or a password-policy change.

The BIOS build timestamp changes from **November 21, 2025, 15:07:21** to **September 22, 2026, 11:44:27**. Flashing-related version checks change from 310 to 312. Several modules also differ in their DOS/NT header placement or embedded build dates.

## Limits of this changelog

I have not tested firmware execution, fan RPM, gaming performance, sleep behavior or GPU stability. I also have unresolved setup routines and EC status transfers. [Coverage](../research/coverage.md) records those gaps.

For this comparison, I used the packages and hashes in [releases.json](../data/releases.json), UEFIExtract A76, iASL 20260408, PSPTool 3.7, Capstone 5.0.9, pefile 2024.8.26 and Ghidra 12.2. The [method](../docs/method.md) explains the confidence labels and address conventions.
