# 309 → 310: embedded controller

The EC controls low-level laptop functions such as charging, fans and power transitions. ASUS includes a different EC build in 310, but a build-number change alone does not establish a change to those policies.

## Image identity

| Field | 309 | 310 |
|---|---|---|
| Board string | `ASUS NJT(GA403W_MB1)` | Same |
| EC version | `03.09F#` | `03.10F#` |
| EC build string | `2025/09/19 b16#` | `2025/10/02 b02#` |
| ITE platform string | `ITE51300-SB-V.00120230800` | Same |
| Raw region SHA-256 | `d64307371d0092a6925f90ce6e0761c15a793d5c12a2cebea4a0e9d7595aa0e3` | `a9ea14f1be459c623f055e03e6c4d0831d5ffad246143d78598ebd7cd1605f59` |

The EC region begins at **capsule-file offset `0x81800`** and occupies **`0x50000` bytes** in both packages. Its version string is at capsule offset `0x897C0`; the date string is at `0x897D0`. EC-relative addresses below use the extracted region as zero. EC RAM maps at **`0x00800000`** in the Ghidra project.

## EC-01: metadata initialization

The initializer at EC-relative **`0x1126E`**, capsule offset **`0x92A6E`**, changes its version and date constants:

| RAM byte | 309 value | 310 value | Interpretation |
|---|---|---|---|
| `0x00800406` | `0x09` | `0x10` | Build month |
| `0x00800407` | `0x19` | `0x02` | Build day |
| `0x00800408` | `0x16` | `0x02` | Build suffix |
| `0x008003E5` | `0x09` | `0x10` | Minor version field |
| `0x0080040B` | `0x09` | `0x10` | Mirrored minor version |

The surrounding initializer retains the board and other identification bytes. The new code reuses the constant 2 for the day and suffix, reducing the recovered function body from **280 to 278 bytes**.

Short instruction excerpt:

```text
309: load a5, 0x09; store a5 to version/month fields
     load a2, 0x19; store a2 to day field
     load a2, 0x16; store a2 to suffix field

310: load a5, 0x10; store a5 to version/month fields
     load a3, 0x02; store a3 to day and suffix fields
```

The interpretation follows the literal build strings and the byte assignments. These constants do not set charging percentages or fan speeds.

## Address movement

The two-byte reduction shifts much of the later application code back by two bytes. Direct calls, branch targets, absolute pointers and relative jump-table entries change to follow it.

Examples checked in the instructions:

| Reference | 309 | 310 |
|---|---|---|
| Call at EC `0x247C` | Target `0x113C2` | Target `0x113C0` |
| Stack setup routine | Entry `0x113C6`, `ADDI -0x7C6` | Entry `0x113C4`, `ADDI -0x7C4` |
| Function beginning at `0x3FB7A` | AUIPC/ADDI table-address pair | Entry moves to `0x3FB78`; ADDI increases by 2, preserving the table address |

In the fixed tail interval `[0x42000, 0x50000)`, 1,470 changed aligned 32-bit fields decrease by 2. Four more aligned-word changes contain the high half of unaligned pointers; reading the pointer fields at `0x45CBE`, `0x45CDA`, `0x45CF6` and `0x45D12` shows the same two-byte adjustment. The fields include absolute addresses and signed relative jump offsets. Counting changed bytes here as changed EC policies would misrepresent the update.

Two header bytes also differ. Their precise integrity-field definition remains unresolved; no policy claim depends on them.

## Function comparison and limits

Ghidra recovered **1,413 candidate boundaries in each image** and produced C for **1,406 in each**. The matcher pairs 1,412 by its instruction heuristic and the metadata initializer by normalized-C similarity. A subsequent instruction pass retains constants while accounting for moved branch/call targets; the remaining reviewed differences are the initializer and address-generation adjustments.

Those heuristics are not an equivalence proof. Some candidate boundaries point into data or share tails, indirect transfers remain unresolved, and the matcher deliberately removes information from its hashes. The whole-image statement supported here is narrower: **no charging threshold, fan curve, or power-budget policy change was identified in the recovered control paths**.

The [candidate pairs](../data/309-310/function-candidates/EC.json), [review metadata](../data/309-310/ec-review.json) and [coverage](309-310-coverage.md) retain the evidence and remaining gaps. Full assembly and decompilation stay local. The [later 310 → 312 EC findings](310-312-ec.md) contain separate behavioral changes and must not be attributed to this pair.
